# 按钮 UI 代码审查

日期：2026-11-10。范围：公共 MotionButton、基础重置、原型工具类、剩余页面公共样式及各页按钮使用方式。针对用户反馈的文字偏上、短按钮接近圆形进行检查。

| 发现 | 原因与证据 | 修复 |
| --- | --- | --- |
| P2：短按钮文字没有垂直居中 | `remaining.css` 只设最小高度；普通块布局按顶部内边距排字。320px下“领取”文字中心向上偏6.19px | 文字操作显式使用 flex 双轴居中；修复后偏移0px |
| P2：短按钮被挤成近圆形 | “领取”等在横向 flex 行中允许收缩，且继承9999px圆角。实测约47.88×44px | 短文字按钮最小72×44px、不收缩、12px圆角；整行主操作使用16px圆角 |
| P2：同一类问题散布多个页面 | 转为 MotionButton 后，原型中的紧凑文本按钮与图标按钮共用工具类，缺乏明确布局类别 | 给文字操作、筛选项、文本链接分别增加 action-label/action-tab/action-link；内容卡片、设置行及真正圆形图标保持原布局 |

已覆盖练习领取、积分任务、订单物流/收货、直播进入/预约、会员续费、推广/提现、报告/海报分享及相关筛选入口。没有修改生产接口、支付或打卡业务逻辑。

复查确认：选择态和按压反馈仍生效；模态与导航锁不触发原生 disabled 白底；设置行保持左侧图标与右侧信息；会员方案卡、商品卡和圆形日历控件未套用短文字按钮布局。

验证：52项浏览器回归通过，类型检查与H5/微信构建通过，微信开发者工具原生预览成功。新增用例在320/375/430px直接测量七种短操作的文字中心、宽高、圆角与横向溢出，并覆盖“领取→说明”和“今日打卡→对应冥想播放器”。

浏览器测量证明布局规则修正，微信原生预览证明可编译；本轮未操作手机验证触摸与字体观感，不将其写为真机验收通过。用户反馈空白页已不再复现，本次不声称定位或修复了其根因。
