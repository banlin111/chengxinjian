# 澄心涧前端开发流程与开工准备

日期：2026年11月9日  
适用范围：微信小程序与 Web 管理后台的页面、交互、动画、三套主题及前端接口对接。  
当前阶段：开发准备。本文件定义执行流程，不代表已经开始应用开发。

**页面与交互规格、交互动效规范已形成草案，下一步进入前端基础工程与页面还原。** 页面视觉直接依据甲方效果图，咱们补齐交互与动效，不另做全新视觉稿。按页面规格中的入口、状态和验收条件逐批实现。

本流程采用需求梳理、交互设计、视觉规范、技术验证、工程搭建、功能实现、联调测试、验收发布的顺序，按两人团队规模执行。业务细节允许逐模块补齐；影响导航、支付、播放器或直播架构的决定应优先落实。

## 一 项目范围与分工

| 参与方 | 负责内容 | 需要交付给对方的东西 |
| --- | --- | --- |
| 咱们前端 | 小程序页面、后台页面、交互与动效、主题、组件、状态展示、接口调用、前端测试 | 可预览页面、页面状态说明、接口需求及异常处理、前端构建产物 |
| 同事后端 | Java / Spring Boot、数据、鉴权、业务规则、支付、直播与存储等服务、部署 | 接口实现、联调地址、测试账号与数据、错误码、服务状态说明 |
| 甲方 | 产品范围、视觉方向、内容、价格和奖励等业务规则、平台资源、业务验收 | 确认记录、素材、配置规则、账号权限、验收反馈 |

管理后台的页面仍属于前端工作。后端决定价格、会员权益、奖励资格和权限，前端负责准确展示服务器结果并完成交互，不在页面里自行判断并发奖或开通会员。

本期沿用 README 的范围：思维导图全部功能、小程序优先、后续 APP，以及浅色宣纸、松石夜色、墨绿三套主题。商城零售、购物车、积分钱包、分销提现等原型新增功能已纳入前端演示占位范围，使用隔离的模拟数据；不新增真实支付、发奖、提现等后端业务。具体范围见[页面与交互规格表](页面与交互规格表.md)。

## 二 开始写业务页面前先完成什么

### 1 把页面清单整理成页面规格

建立一份页面表，逐页记录下列字段。每个页面使用稳定编号，便于对应设计、接口、任务与验收。

| 字段 | 要说明的问题 |
| --- | --- |
| 页面编号与名称 | 这是哪个页面，属于小程序还是管理后台？ |
| 页面用途 | 用户来这里完成什么事情？ |
| 来源与入口 | 对应 README 哪个功能，从首页、列表还是分享进入？ |
| 导航与返回 | 主按钮跳到哪里，返回后是否保留筛选和滚动位置？ |
| 用户身份 | 游客、普通用户、会员、讲师、管理员分别能看到和操作什么？ |
| 内容结构 | 哪些区域、字段、图片和按钮必须出现？ |
| 页面状态 | 正常、加载、空数据、失败、无权限及业务特殊状态如何展示？ |
| 动效 | 哪个动作触发、持续多久、何时停止、是否可降级？ |
| 数据与接口 | 哪些是本地偏好，哪些来自后端，依赖哪个接口？ |
| 复用关系 | 是否与其他页面共用模板、表单或组件？ |
| 验收条件 | 用户执行哪些动作，应该出现什么可观察结果？ |
| 待确认项 | 问题是什么、谁能决定、是否阻塞当前页面？ |

示例：

| 字段 | 课程详情页示例 |
| --- | --- |
| 编号 | MP-COURSE-DETAIL |
| 入口 | 首页推荐、课程列表、搜索结果、分享 |
| 内容 | 封面、标题、讲师、介绍、课节目录、学习进度、收藏、试听或购买入口 |
| 身份与权限 | 游客可浏览；试听与解锁状态由服务端返回；购买前登录 |
| 状态 | 加载中、正常、课程下架、加载失败、已解锁、未解锁 |
| 点击行为 | 选择可播放课节进入播放器；未解锁课节展示解锁操作；收藏后更新状态 |
| 接口 | 课程详情、课节列表、收藏、播放授权；购买流程单独进入报价与订单接口 |
| 验收 | 课程信息可读；返回保持原列表位置；接口失败可重试；不能播放未授权的完整内容 |

页面规格先覆盖第一条开发流程，其余模块可继续细化。一个表单的新增/编辑、同页的多个标签、成功/失败状态不必各建一个独立页面。

### 2 明确导航和主要操作流程

小程序底部导航已确认按V2首页图固定为“推荐、冥想、课程、练习、我的”，默认墨绿主题；商城与直播从推荐快捷入口进入，商城也在我的保留入口。管理后台先定模块菜单与讲师、运营、财务等角色可见范围。

至少梳理下面六条流程，并明确取消、失败和返回的位置：

1. 浏览课程 → 查看详情 → 试听或解锁 → 播放 → 查看学习记录。
2. 登录 → 完成必要授权或手机号绑定 → 返回原操作页面。
3. 选择练习 → 设置时长或音轨 → 开始与暂停 → 完成 → 打卡与查看奖励。
4. 录制或选择文件 → 预览 → 上传 → 提交审核 → 查看结果 → 领取奖励。
5. 选择会员或单课 → 确认购买 → 调起支付 → 查询结果 → 使用权益。
6. 预约直播 → 授权提醒 → 进入直播 → 提问或评论 → 结束后查看回放。

后台同步梳理课程发布、录制审核、奖品发货、直播控制和退款处理流程，避免出现用户端有入口但后台无法维护数据的情况。

### 3 提取原型样式并补齐动效

用户已明确页面视觉直接按甲方效果图还原，不另起全新视觉设计。以墨绿V2为默认页面依据，V1补齐未覆盖的页面，保留三套主题。缺少原型的辅助页沿用既有风格，后台按已有功能规格补齐。

提取原型的字体、间距、圆角、图片比例和组件状态，作为实现参数；素材不全时明确标记占位。点击反馈、弹层、加载、播放器和打卡等动效按[交互动效实现规范](交互动效实现规范.md)实现。

后续直接用可运行页面核对还原效果，不把重新制作视觉稿作为开工前提。

## 三 整体阶段和完成条件

| 阶段 | 核心工作 | 交付物 | 进入下一步的条件 |
| --- | --- | --- | --- |
| 1 需求与页面梳理 | 核对范围、页面、角色、跳转、关键状态、待确认规则 | 页面规格表、流程图、问题清单 | 第一批页面入口与操作路径明确，关键范围没有冲突 |
| 2 原型样式与动效规范 | 提取既有原型样式、三主题、点击与状态动画 | 原型样式参数、交互动效规范 | 已有视觉依据，动效触发及停止条件明确，可开始还原 |
| 3 技术与接口验证 | 核对契约、验证核心平台能力、确定状态与错误处理 | 技术决定记录、第一批接口样例、风险处理方案 | 影响整体结构的可行性问题有结论或明确降级方案 |
| 4 工程与公共基础 | 建工程、路由、主题、请求层、Mock、代码检查、公共组件 | 可运行的基础工程与组件预览 | 两人按说明可启动，能切换 Mock/真实接口，基础构建通过 |
| 5 按流程实现功能 | 同时完成页面布局、交互、状态、动效及接口接入 | 每批可演示的功能闭环 | 对应流程及异常路径可操作，不只是页面截图 |
| 6 联调与质量检查 | 真数据、真机、权限、弱网、性能、兼容性 | 问题清单、修复记录、测试证据 | 核心流程通过，阻断问题清零，其余问题明确处置 |
| 7 验收和交付 | 逐项核对范围、体验版、发布准备、操作说明 | 验收记录、发布产物、版本及维护说明 | 甲方验收完成，发布权限与环境就绪后安排上线 |

第2、3阶段可以部分并行；技术验证发现限制时及时回到交互与视觉设计调整。一次评审集中处理一批页面，日常颜色、间距、组件实现由前端按已定规范推进，不必每个按钮都单独请示。

## 四 视觉和动画应怎样规范

### 三套主题

颜色使用语义名称，例如背景色、卡片色、主要文字、次要文字、主按钮、强调色、边框、成功和错误色。实际颜色沿用 README 已采集的三套色板。

同一页面共用结构与逻辑；切换主题时覆盖导航栏、TabBar、图标、播放器、弹窗、图表及加载状态。用户切换主题不应丢失播放进度、已输入内容或当前导航位置。

### 公共视觉规范

统一字体层级、行高、间距、圆角、图标尺寸、图片比例和按钮状态。设计稿尺寸用于表达比例；实际实现需要适配微信胶囊、安全区、小屏手机和较大字体。后台表格需考虑列宽、长文本、省略与详情查看，以及键盘操作和清晰的焦点状态。

### 动效规格

动效表至少包含触发条件、作用对象、时长、缓动、是否循环、停止条件和降级方式。以下为概要，具体参数及验收以[交互动效实现规范](交互动效实现规范.md)为准，实现后根据真机体验微调：

| 动效 | 触发与表现 | 运行约束 |
| --- | --- | --- |
| 首页水波 | 页面可见时缓慢移动，建议循环12～20秒 | 页面隐藏停止；低性能场景改静态背景 |
| 播放器呼吸光晕 | 播放时轻微明暗或缩放，建议循环4～6秒 | 暂停或离开时停止；属于视觉反馈，不表示医疗指导节奏 |
| 弹层进出 | 打开/关闭时淡入与轻位移，建议180～250毫秒 | 关闭后销毁无用监听，不阻塞返回操作 |
| 按钮反馈 | 点击后轻微变化，建议80～150毫秒 | 同步显示忙碌态，防止误以为没响应而重复提交 |
| 倒计时进度 | 与真实计时状态同步变化 | 用时间差计算，不能靠动画帧数充当计时器 |
| 打卡与领奖 | 成功后短时反馈，建议300～600毫秒 | 只在服务端确认成功后显示，不遮挡结果和下一步 |
| 直播点赞 | 点击或收到聚合事件时出现飘心 | 限制同时存在的元素数和触发频率 |

用户可减少持续动画；减少动画时保留必要的状态文字。音频、直播播放能力与视觉动效分开验收，动画顺畅不代表后台播放已验证。

## 五 开工后的技术准备

本节是后续执行事项，本次不创建工程或验证原型代码。

### 工程基础

沿用 README：小程序使用 uni-app、Vue 3、TypeScript；后台使用 Vue 3；后端由同事采用 Java / Spring Boot。建立工程时固定工具与依赖版本、提交锁文件，写清安装、启动、构建与环境切换步骤。

小程序与后台分别构建，共享接口类型及必要的业务工具。请求层统一处理地址、token、超时、错误码、刷新登录和取消请求；页面通过 API 模块取数据，不直接散写请求。

业务组件按实际重复场景提取，例如课程卡片、权限标签、媒体播放器、音量滑杆、状态展示、地址表单。先满足已有页面，再扩大复用范围。

### 与后端先对齐第一批契约

README 和 OpenAPI 目前属于契约草案。接口数量不等于页面数量，也不表示所有接口已经实现。双方先逐项核对第一条开发流程需要的接口：

- 请求字段、返回样例、可空字段、枚举和金额/时长单位。
- 游客、普通用户、会员的返回差异及权限来源。
- 加载失败、登录过期、内容下架、无权益等错误处理。
- 分页方式、重复提交规则、测试账号及测试数据。
- 前端收到“处理成功”和收到“处理中”时各应显示什么。

Mock 数据按同一契约覆盖正常、空数据、失败和权限状态，切换真实接口时不需要重写页面结构。接口变更先更新契约与样例，再同步两端；发现现有契约缺口时记录并共同修正。

### 提前验证的平台能力

开始批量开发前，给背景音频、前台多轨混音、直播播放器、录制上传和虚拟支付分别安排最小验证。没有真实账号条件时，先隔离平台调用并展示可替换的模拟状态；该能力仍标为待真机验证。

微信原生授权和支付界面由平台提供，前端制作其触发入口、说明、取消和结果状态，不仿制系统界面来代替真实能力。尤其不要在未验证前把五轨后台混音当成已能交付的效果。

| 资源 | 页面及设计阶段 | 真实能力联调阶段 |
| --- | --- | --- |
| 小程序 AppID 与开发成员权限 | 不阻塞页面规格和视觉设计 | 正式项目预览、上传、相关微信能力联调时落实 |
| 后端地址与测试账号 | 可先用契约及 Mock | 接真实数据与身份权限时必须具备 |
| AppSecret、支付和云服务密钥 | 前端不需要 | 同事在后端配置，前端不接收和保存 |
| 甲方素材与规则 | 缺失时可明确使用占位 | 正式验收前替换为最终素材及规则 |

## 六 第一批功能怎样推进

建议先完成“浏览课程到恢复学习”这一条可演示流程，以它验证项目基础，而不是先铺开所有页面。

1. 首页展示推荐和继续播放入口。
2. 课程库能分类、筛选并保留返回位置。
3. 课程详情展示目录、试听与解锁状态。
4. 播放器完成播放、暂停、进度、倍速和必要的状态反馈。
5. 我的学习能看到记录，并回到对应课节。
6. 后台能创建、编辑和发布这条流程使用的课程及课节。

同时覆盖浅色宣纸、松石夜色、墨绿主题，并演示空列表、失败重试、未登录和未解锁状态。登录作为本批的基础依赖接入；付费部分可先模拟权益分支，真实支付在交易批次验收，不能据此声称已打通购买。

后续按练习与打卡、录制和奖励、会员交易、直播回放、后台运营及统计依次形成完整流程。最终顺序可根据后端可用接口和平台开通进度调整，但不减少已确定的总范围。

## 七 什么才算一个前端页面完成

一个页面必须同时满足以下条件，才从“开发中”转为“可验收”：

- 结构、内容层级和三套主题符合已定设计；不存在明显遮挡或文字不可读。
- 所有可见按钮有明确行为；返回、取消、二次进入和分享入口的行为一致。
- 具备加载、空数据、失败重试及相关权限状态；长标题、缺图和极端数值不破坏布局。
- 数据来自统一 API 或明确标记的 Mock；接真实服务后验证字段和错误处理。
- 动画按条件启动和停止，页面离开后清理计时器、监听与临时资源。
- 对表单校验、防重复点击、上传中断等交互提供明确反馈。
- 在约定手机或浏览器尺寸验证通过；小程序核心能力另留真机证据。
- 有对应页面编号、接口依赖、可复现的验收步骤和已知问题记录。

至少为登录状态、播放状态、提交去重和关键业务流程安排有意义的测试。颜色微调、纯文案等低风险改动以视觉检查为主，不为每个样式写重复实现的单元测试。

## 八 联调和交付的检查方式

| 检查类型 | 重点 | 记录方式 |
| --- | --- | --- |
| 设计核对 | 布局、字体、素材、主题、动画 | 同一设备与数据下截图对比；关键动效录屏 |
| 功能联调 | 页面跳转、接口字段、权限、表单、异常恢复 | 用户操作步骤、实际结果、请求编号 |
| 真机兼容 | Android 与 iPhone、安全区、较大字体、键盘、锁屏和返回 | 机型、系统/微信版本、结果及问题 |
| 性能 | 首次可用内容、列表滚动、图片加载、混音和动效负载 | 固定设备与网络下测量，建立基线后共同确定数值目标 |
| 后台可用性 | 表格筛选、批量数据、长表单、键盘操作、权限菜单 | 代表性账号和操作清单 |
| 发布准备 | 生产环境地址、关闭 Mock、域名配置、审核素材、版本号 | 发布检查记录和可回退版本 |

发现问题按“阻断主要流程、影响功能、视觉细节”区分优先级。每次调整只复查受影响的部分，并保留一轮核心流程回归。性能目标要附设备与网络条件，不承诺没有测量依据的“全机型流畅”。
