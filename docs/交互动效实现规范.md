# 澄心涧交互动效实现规范

日期：2026年11月10日  
适用范围：微信小程序与 Web 管理后台；对应[页面与交互规格表](页面与交互规格表.md)。

**页面布局和视觉样式按甲方效果图还原，咱们设计点击反馈、状态变化和必要的过渡动画。** 不再安排一轮全新视觉稿。缺少效果图的辅助页沿用原有组件、字体和颜色；后台缺少完整原型的部分按既定表单、列表和权限需求补齐。

最新视觉基准为 PDF 松石夜色版，保留其他主题的底层配置。底栏固定为“推荐、冥想、课程、练习、我的”。动效不改变页面结构与业务行为。

## 当前实现：S1 推荐首页与 S2 冥想

按用户最新安排逐页精修和制作动效，当前已推进首页、冥想及分类/详情补全页，其余页面按 PDF 顺序继续。观感参考 [Apple Motion 指南](https://developer.apple.com/design/human-interface-guidelines/motion)的简短、直接、跟随手势和可减少动画原则，下面时长为项目调校值，不是 Apple 官方规定。共享元素设计参考 [Apple 流畅转场](https://developer.apple.com/documentation/uikit/enhancing-your-app-with-fluid-transitions)和 [Motion 布局动画](https://motion.dev/docs/react-layout-animations)，实现适配 uni-app；没有引入仅适用于 React 或 UIKit 的运行库。

| 触发 | 已实现行为 |
| --- | --- |
| 按住首页课程卡片 | 90ms 缩至 0.985，并轻微降低不透明度 |
| 点击首页大卡/每周上新 | 340ms 共享元素转场：封面从源卡片移动到播放器圆形封面位置并变圆；完整播放器布局同步显现，过渡期间隐藏目标封面副本，避免重影。微信端结束后直接操作同页播放器，H5进入同布局路由 |
| 按住打卡按钮 | 90ms 缩至 0.97，松开以 320ms 缓出恢复；不等待动画才导航 |
| 更多链接 | 44px 点击高度，轻微缩放与明暗反馈 |
| 滚动、取消触摸、离开页面 | 清除按压；超过 8px 的拖动不触发课程跳转 |
| 首次内容到达、回到主页面 | 稳定显示，不播放浮现位移；不重建课程列表 |
| 横滑上新卡片 | 平台滚动惯性，返回保留横滑位置；不自动轮播 |
| 加载和错误 | 与首页结构接近的骨架轻柔明暗；错误状态直接显示并可重试 |
| 连续点击 | 导航期间拦截重复调用，失败解除锁定并提示 |
| 减少动画 | H5 尊重 `prefers-reduced-motion`；同时支持已有 `cxj.reducedMotion` 本地设置，只保留明暗反馈 |

首页底部采用弹性布局，打卡卡片距真实底栏保留 16px；高屏适当增大主图和栏目间距，短屏允许滚动。没有新增填充内容。展开过渡退出页面即取消，导航失败清除遮罩，减少动画时跳过展开直接导航。当前返回仍使用平台导航，不含反向缩回卡片的动画。

S2 八宫格采用轻微缩放，透明度恒为1；导航中使用逻辑忙碌锁，避免原生禁用样式闪动。分类入口进入独立列表、详情、播放，不再在主页替换词条。主底栏切换不做整页浮现位移。MotionButton 已用于 S1、S2 和冥想补全页。

普通子页使用一次平台导航。S1 微信端卡片展开后保留同页播放器，避免再接一次原生跳转；H5进入对应播放路由。不会宣称完全复刻 UIKit 交互。触感和帧率仍需真机确认，检查方法及目标见[前端性能验收](前端性能验收.md)。以下未明确标注实现的动效仍为后续规范。

## 一 动效基准

以下是初始实现参数，代码实现后根据真机体验微调。原型已有水波、呼吸等视觉表现时保留其风格；交互反馈采用统一参数。

| 参数 | 初始值 | 用途 |
| --- | --- | --- |
| press | 100ms | 按下反馈 |
| release | 150ms | 松开后恢复 |
| state | 180ms | 标签、图标、颜色切换 |
| overlayIn | 240ms | 弹层进入 |
| overlayOut | 180ms | 弹层退出 |
| success | 400ms | 一次性完成反馈 |
| easeOut | cubic-bezier(0.2, 0, 0, 1) | 弹层进入、状态恢复 |
| easeIn | cubic-bezier(0.4, 0, 1, 1) | 弹层退出 |
| linear | 匀速 | 与真实进度同步的移动 |

循环装饰动画不能作为计时、播放进度、用户活跃或业务成功的依据。普通操作不因装饰动画延迟；用户指定的首页卡片展开作为导航过渡，340ms 完成后进入目标页，减少动画时直接进入。

## 二 通用点击和导航

| 对象 | 触发与表现 | 完成或中断规则 |
| --- | --- | --- |
| 主按钮 | 按下100ms缩放到0.98；松开150ms恢复 | 移出点击范围或取消触摸时恢复；禁用态不触发 |
| 图标按钮 | 按下轻微底色变化；松开恢复 | 保留原型图标和点击区域，不能靠动画改变布局 |
| 内容卡片 | 按下缩放到0.99并轻微改变遮罩 | 滚动手势取消按压态；列表多个卡片不能同时持续缩放 |
| 底栏 | 点击立即切换选中图标与文字色，180ms过渡 | 页面切换遵循小程序原生导航；不叠加整屏自制滑动，不闪白 |
| 页内标签 | 文字/底色180ms切换，指示条跟随 | 只保留最后一次筛选结果，旧请求不能覆盖新标签 |
| 页面前进返回 | 使用平台导航行为 | 返回保留列表筛选和滚动；不能为了动效延迟返回 |
| 收藏或点赞 | 点击后图标短暂放大至1.12再恢复，共240ms | 可乐观更新，接口失败回滚并提示；真实与演示状态分开 |
| 开关 | 颜色与滑块180ms过渡 | 保存失败恢复原值；权限拒绝不能仍显示已开启 |
| 滑杆 | 拖动时滑块和数值直接跟手 | 拖动过程中不加缓动，不在每一帧发网络请求；松开后持久化 |

网络写操作进入忙碌态后禁重复提交，文字改为“保存中”等对应状态。点击防重复与后端幂等共同使用；不能仅靠按钮动画防止重复交易。

## 三 弹窗和表单

| 组件 | 进入 | 退出 | 操作规则 |
| --- | --- | --- | --- |
| 底部操作面板 | 从底部移动到位，240ms；遮罩同步淡入 | 180ms下移并淡出 | 用于倍速、定时、筛选、规格；普通选择可点遮罩关闭 |
| 中央确认框 | 透明到不透明、缩放0.96到1，180ms | 150ms淡出 | 退款、注销、提现说明等必须有清晰取消/确认；不误触执行 |
| 后台侧边抽屉 | 从右侧进入，240ms | 180ms离开 | 保存中显示进度；未保存退出提醒；关闭后焦点回到触发按钮 |
| 简短提示 | 150ms淡入，默认约2秒后淡出 | 用户新操作可结束旧提示 | 重要失败保留页面内重试，不只用稍纵即逝的提示 |
| 表单校验 | 字段下方显示文字，必要时滚动到首个错误 | 修正后清除 | 不用剧烈抖动；不清空用户已输入的内容 |

弹层打开时限制底层误触，处理键盘与底部安全区。关闭、系统返回和取消触摸都能清除遮罩，不能留下不可点击的透明层。微信授权、订阅消息、支付和系统确认界面使用平台原生能力，不制作外观相似的假授权窗口。

## 四 加载和异常

- 首次取数使用与内容布局一致的骨架，避免整页高度跳动。可用约1.5秒的轻柔明暗循环；减少动画时静态展示。
- 列表加载更多只在尾部显示状态，已有内容保持可读。失败显示“重试”，不把整个列表清空。
- 上传进度来自真实已上传字节；处理/转码阶段改为不定进度，不编造持续前进的百分比。演示上传使用明显的模拟标识。
- 网络慢时持续显示处理中和必要的退出说明，不无限播放“马上成功”的动画。付款状态不明时提供查单入口，不能引导用户反复支付。
- 空数据、内容下架、权限不足和接口失败是不同状态，使用对应文字与动作，不共用一个“暂无数据”遮掩错误。

## 六 资源和兼容性约束

装饰动效优先使用不改变页面排版的透明度与变换。轨道、卡片等连续交互避免每帧触发整个页面的数据更新。页面隐藏或卸载时清理无用计时器、动画、事件监听；全局音频由统一播放控制器管理，不能随页面退出误销毁。

同一控件统一处理触摸结束、触摸取消、失焦和切后台，避免按钮停留在按下状态。屏幕阅读、较大字体和减少动画模式下，文字、图标、按钮状态仍能独立传达含义。提供减少持续装饰动画的本地设置，不依赖所有平台都具备同一系统偏好API。

小程序主页面按手机真机检查，后台按桌面浏览器检查。后台列表与表单使用较轻的过渡，不套用沉浸播放器的呼吸效果。不能用H5预览正常替代微信端的媒体和原生组件验收。

## 七 首批实现顺序

1. 建立前端基础工程，配置三主题、原型素材引用、五项固定底栏、Mock数据和公共状态组件。
2. 还原墨绿推荐页与课程库，加入通用点击、标签、加载和返回状态。
3. 还原课程详情与播放器，接入统一媒体控制层及呼吸/进度动效；后端未就绪时明确使用Mock状态。
4. 补上我的学习与一次完整浏览播放流程，再检查另外两套主题。
5. 以商城详情和购物车验证演示交互；随后按页面规格表推进其他页面及后台。

上述是后续应用实现的任务安排，本次仅形成规范。开始实现后展示实际可运行页面供用户核对还原效果，不再以制作全新视觉稿作为开工前提。像素差异、素材缺失和原型矛盾集中记录；已确认的底栏和默认主题不再反复询问。

## 播放器入口统一（2026-11-11）

首页、课程详情试听、冥想详情、练习打卡、直播回放使用同一 `PlayerTransition` 视图及 `useCardExpansion` 动画参数：340ms，cubic-bezier(.22,1,.36,1)。首页保留原有状态控制；其余入口由 `usePlayerTransition` 统一管理锁定、返回与生命周期。

可见封面移动到播放器168px圆形封面；封面已滚出视口时，以当前操作所在容器为起点。只有按钮的入口只展开背景/页面，封面以最终尺寸淡入，不把按钮或照片拉伸成大图。测量无结果或启用减少动态效果时直接打开可操作播放器。

微信端使用同页 PlayerScene，展开结束不再 navigateTo，避免退回源页后又出现原生路由动画。练习主标签隐藏/恢复底栏；二级页面不修改底栏。page-container接管返回关闭播放器；进入混音再返回保留播放器。动画未完成就离开时取消延迟操作。网页端动画完成后仍进入播放器路由，返回保留来源页面状态。

代码审查发现微信测量自定义按钮宿主可能返回0×0，已给打卡/冥想按钮及课程课节添加真实view测量容器；页面文字、图片和播放参数保持对应。原生绘制确认增加超时保护，避免测量回调未返回造成操作锁定。

验证：55项浏览器回归通过，类型检查及双端构建通过。微信工具原生运行时检查课程、冥想、打卡、回放四入口，均存在有效起点、完成展开且页面栈仍为1；关闭均恢复源页，另核验课程播放器进入混音后返回状态。可使用 `apps/mobile/scripts/check-player-transition-native.cjs` 重跑原生状态检查（需当前构建已开启自动化端口）。该脚本触发组件事件并检查原生状态，不等同于真机手势/帧率验收。
